# Making Prysm Agent-Ready: An Actionable Improvement Plan

**Context:** Follow-up to the efficiency analysis. This report provides concrete, prioritized changes the team can make to the Prysm codebase so that coding agents can handle more tasks safely and autonomously.

**Principle:** Every recommendation works by converting **implicit knowledge into explicit, machine-readable structure** — things agents can read, check, and follow without needing to carry the team's mental model.

---

## Part I: High-Impact, Low-Effort (Do This Week)

### 1. Create a CLAUDE.md That Encodes the Team's Mental Model

The `.claude/` directory already exists with `settings.local.json` granting `go test`, `bazel build`, and `hack/` script permissions. But there is **no CLAUDE.md** — the single most important file for agent effectiveness.

**What to write:**

```markdown
# CLAUDE.md — Prysm Agent Instructions

## Build & Test
- Use `go test ./path/to/package -run TestName -timeout 30s` for unit tests.
- State-native tests REQUIRE Bazel: `bazel test //beacon-chain/state/state-native:go_default_test`
- After modifying .proto files: `./hack/update-go-pbs.sh`
- After modifying SSZ structs: `./hack/update-go-ssz.sh`
- After modifying interfaces used in mocks: `./hack/update-mockgen.sh`
- After adding/removing Go files: run Gazelle via `bazel run //:gazelle`

## Do NOT Edit Generated Files
- Files matching `*.pb.go` are generated from `.proto` files
- Files matching `*.ssz.go` are generated from SSZ structs
- Files in `testing/mock/` are generated by mockgen
- If you need to change these, edit the source and run the corresponding hack/ script

## State Setter Protocol (CRITICAL)
Every setter method on BeaconState MUST follow this exact sequence:
1. Acquire `b.lock.Lock()` (use write lock, not read lock — setters may trigger lazy recomputation)
2. For fields with `sharedFieldReferences`: check `Refs() > 1`, copy-on-write if shared
3. Perform the mutation
4. Call `b.markFieldAsDirty(types.FieldName)`
5. For element-level updates: also call `b.addDirtyIndices(types.FieldName, indices)`
6. For full replacements: also set `b.rebuildTrie[types.FieldName] = true`
Missing step 4 causes stale HashTreeRoot. Missing step 2 corrupts shared state copies.

## Fork Versioning
- 8 active forks: Phase0, Altair, Bellatrix, Capella, Deneb, Electra, Fulu, Gloas
- New fork-specific fields need version guards: `if b.version < version.Xxx { return errNotSupported(...) }`
- Adding a field touches: types/types.go, config/params, state-native getters+setters, interfaces.go, proofs.go validateFieldIndex, state_trie.go field arrays
- When unsure about which versions support a field, check types.FieldIndex.RealPosition()

## Proof Generation
- `ProofByFieldIndex` uses FieldIndex enum (compile-time safe, preferred for internal use)
- `ProofByFieldPosition` uses integer position (runtime, for SSZ query API where field is resolved dynamically)
- Merkle proofs are sensitive to off-by-one errors. Always verify with spec tests.

## Lock Ordering
- State lock (`b.lock`) is always acquired FIRST, outermost
- Field trie locks are acquired SECOND, inside state lock
- Reference counter locks are acquired via sharedFieldReferences methods (innermost)
- NEVER acquire state lock while holding a field trie lock (deadlock)
- Use write lock (Lock) not read lock (RLock) for any method that calls initializeMerkleLayers or recomputeDirtyFields

## Architecture
- Service initialization order in beacon-chain/node/node.go is critical — later services depend on earlier ones
- Event feeds (StateFeed, BlockFeed) are the primary inter-service communication mechanism
- The blockchain service is the central hub — changes there ripple to all consumers
```

This single file immediately makes agents aware of the COW protocol, lock ordering, generated file boundaries, and build commands. Every item above is knowledge that currently lives only in developer heads.

## Part II: Medium-Effort, High-Impact (Do This Sprint)

### 4. Replace the validateFieldIndex Switch With a Data-Driven Lookup

The 7-branch switch statement in `proofs.go:230-263` is repeated in many places and is the #1 place where adding a new fork requires edits. Replace it with a single lookup:

**Before (repeated ~10 times across the codebase):**
```go
func (b *BeaconState) validateFieldIndex(f types.FieldIndex) error {
    switch b.version {
    case version.Phase0:
        if f.RealPosition() > params.BeaconConfig().BeaconStateFieldCount-1 {
            return errNotSupported(f.String(), b.version)
        }
    case version.Altair:
        // ... repeated 7 more times
    }
    return nil
}
```

**After (single source of truth):**
```go
// In config/params/ or beacon-chain/state/state-native/
func FieldCountForVersion(v int) (int, error) {
    cfg := params.BeaconConfig()
    counts := map[int]int{
        version.Phase0:    cfg.BeaconStateFieldCount,
        version.Altair:    cfg.BeaconStateAltairFieldCount,
        version.Bellatrix: cfg.BeaconStateBellatrixFieldCount,
        version.Capella:   cfg.BeaconStateCapellaFieldCount,
        version.Deneb:     cfg.BeaconStateDenebFieldCount,
        version.Electra:   cfg.BeaconStateElectraFieldCount,
        version.Fulu:      cfg.BeaconStateFuluFieldCount,
        version.Gloas:     cfg.BeaconStateGloasFieldCount,
    }
    c, ok := counts[v]
    if !ok {
        return 0, fmt.Errorf("unknown version %d", v)
    }
    return c, nil
}

func (b *BeaconState) validateFieldIndex(f types.FieldIndex) error {
    maxField, err := FieldCountForVersion(b.version)
    if err != nil {
        return err
    }
    if f.RealPosition() > maxField-1 {
        return errNotSupported(f.String(), b.version)
    }
    return nil
}
```

**Agent impact:** When the next fork is added, an agent only needs to add one entry to the map, not hunt down ~10 switch statements. The function is also easily discoverable via `FieldCountForVersion` search.

### 5. Build a COW Setter Linter (Extend Existing Analyzer Infrastructure)

Prysm already has 18 custom `go/analysis` linters in `tools/analyzers/`. Add one more:

**`tools/analyzers/cowsetter/analyzer.go`** — An AST-based checker that:

1. Finds all methods matching `func (b *BeaconState) Set*` or `func (b *BeaconState) Append*` or `func (b *BeaconState) Update*`
2. Checks that each one calls `b.markFieldAsDirty(...)` at least once
3. Checks that each one acquires `b.lock.Lock()` before any mutation
4. Warns if a setter accesses `b.sharedFieldReferences` without checking `Refs() > 1`

This is a targeted investment — it catches the exact class of bug that agents introduce most often (forgetting `markFieldAsDirty` or the COW check). The existing analyzer infrastructure (Bazel nogo integration, `nogo_config.json` exclude patterns) makes deployment straightforward.

**Estimated scope:** ~200 lines of Go (similar to `recursivelock/analyzer.go`). Catches the most dangerous class of agent-introduced bugs.

### 6. Create a Fork Addition Checklist Script

Turn the implicit "add a new fork" workflow into an executable checklist:

**`hack/new-fork-checklist.sh`:**
```bash
#!/bin/bash
# Validates that a new fork has been fully wired up.
# Usage: ./hack/new-fork-checklist.sh Gloas

FORK=$1
FORK_LOWER=$(echo "$FORK" | tr '[:upper:]' '[:lower:]')

echo "Checking fork: $FORK"

# 1. Version constant exists
grep -q "version.$FORK" runtime/version/version.go || echo "MISSING: version constant"

# 2. Field count defined
grep -q "BeaconState${FORK}FieldCount" config/params/mainnet_config.go || echo "MISSING: field count in mainnet config"

# 3. Field array in state_trie.go
grep -q "${FORK_LOWER}Fields" beacon-chain/state/state-native/state_trie.go || echo "MISSING: field array in state_trie.go"

# 4. validateFieldIndex handles the version
grep -q "version.$FORK" beacon-chain/state/state-native/proofs.go || echo "MISSING: version in validateFieldIndex"

# 5. InitializeFromProto function
grep -q "InitializeFromProto${FORK}" beacon-chain/state/state-native/state_trie.go || echo "MISSING: InitializeFromProto${FORK}"

# 6. Spec tests
ls testing/spectest/mainnet/${FORK_LOWER}__* > /dev/null 2>&1 || echo "MISSING: mainnet spec tests"
ls testing/spectest/minimal/${FORK_LOWER}__* > /dev/null 2>&1 || echo "MISSING: minimal spec tests"

echo "Done."
```

**Agent impact:** An agent implementing a new fork can run this script to validate completeness. More importantly, it documents the exhaustive list of touchpoints — which currently exists only in the team's collective memory.

## Part III: Structural Refactors (Do This Quarter)

### 7. Extract COW Helpers Using Go Generics

The COW protocol is repeated ~40 times across setter files with minor variations. Extract the two dominant patterns into typed helpers:

**`beacon-chain/state/stateutil/cow.go`:**
```go
package stateutil

// CowAppend performs a copy-on-write append on a shared slice.
// Returns the new slice after appending val.
func CowAppend[T any](
    refs map[types.FieldIndex]*Reference,
    field types.FieldIndex,
    current []T,
    val T,
) []T {
    slice := current
    if refs[field].Refs() > 1 {
        slice = make([]T, len(current), len(current)+1)
        copy(slice, current)
        refs[field].MinusRef()
        refs[field] = NewRef(1)
    }
    return append(slice, val)
}

// CowReplace performs a copy-on-write full replacement on a shared slice.
func CowReplace[T any](
    refs map[types.FieldIndex]*Reference,
    field types.FieldIndex,
    newValue []T,
) {
    refs[field].MinusRef()
    refs[field] = NewRef(1)
}
```

**Before (setters_eth1.go):**
```go
func (b *BeaconState) AppendEth1DataVotes(val *ethpb.Eth1Data) error {
    b.lock.Lock()
    defer b.lock.Unlock()

    votes := b.eth1DataVotes
    if b.sharedFieldReferences[types.Eth1DataVotes].Refs() > 1 {
        votes = make([]*ethpb.Eth1Data, 0, len(b.eth1DataVotes)+1)
        votes = append(votes, b.eth1DataVotes...)
        b.sharedFieldReferences[types.Eth1DataVotes].MinusRef()
        b.sharedFieldReferences[types.Eth1DataVotes] = stateutil.NewRef(1)
    }
    b.eth1DataVotes = append(votes, val)
    b.markFieldAsDirty(types.Eth1DataVotes)
    b.addDirtyIndices(types.Eth1DataVotes, []uint64{uint64(len(b.eth1DataVotes) - 1)})
    return nil
}
```

**After:**
```go
func (b *BeaconState) AppendEth1DataVotes(val *ethpb.Eth1Data) error {
    b.lock.Lock()
    defer b.lock.Unlock()

    b.eth1DataVotes = stateutil.CowAppend(b.sharedFieldReferences, types.Eth1DataVotes, b.eth1DataVotes, val)
    b.markFieldAsDirty(types.Eth1DataVotes)
    b.addDirtyIndices(types.Eth1DataVotes, []uint64{uint64(len(b.eth1DataVotes) - 1)})
    return nil
}
```

**Agent impact:** Reduces the COW protocol from a 6-line inline pattern to a 1-line helper call. Agents can't forget the `Refs() > 1` check because it's inside the helper. The remaining `markFieldAsDirty` and `addDirtyIndices` calls become the only things the linter (Recommendation 5) needs to check.

### 9. Eliminate the Runfiles Barrier for `go test`

State-native tests fail under `go test` because they depend on `bazel.Runfile()` for test data. This blocks agents from running the fastest possible feedback loop.

**Options:**

**A. Embed test fixtures using `//go:embed` (preferred):**
Replace `bazel.Runfile("path/to/testdata")` with `//go:embed testdata/*` directives. This makes test fixtures available to both `go test` and `bazel test`.

**B. Create a test helper that falls back to relative paths:**
```go
func TestDataPath(t *testing.T, path string) string {
    // Try Bazel runfiles first
    if p, err := bazel.Runfile(path); err == nil {
        return p
    }
    // Fall back to relative path for go test
    return filepath.Join("testdata", path)
}
```

**Agent impact:** When agents can run `go test ./beacon-chain/state/state-native/ -run TestProof -timeout 10s` and get results in <1 second, they can iterate 10x faster. Currently, falling back to Bazel adds latency and complexity.

## Part IV: Agent Workflow Design (Team Practice)

### 11. Define Agent-Appropriate Task Boundaries

Not all tasks should be delegated to agents. Establish explicit categories:

| Category | Agent Role | Human Role | Examples |
|----------|-----------|------------|---------|
| **Green Zone** | Agent implements autonomously | Review PR | Refactoring, test generation, error message improvement, HTTP handler boilerplate, doc comments |
| **Yellow Zone** | Agent drafts, human reviews carefully | Verify spec compliance, check invariants | Adding a getter/setter (following existing pattern), updating version switches, updating proto fields |
| **Red Zone** | Agent researches and proposes only | Human implements | State transition logic, Merkle proof math, fork choice changes, BLS operations, P2P message handling |

Put this table in `CLAUDE.md` so the agent self-limits. An agent reading "Red Zone: Merkle proof math" will flag uncertainty rather than silently writing incorrect proof code.

### 12. Establish an Agent Pre-Commit Hook

Add a lightweight hook that runs before agent-generated commits to catch the most common mistakes:

**`.claude/hooks/pre-commit.sh` (or via Claude Code hooks):**
```bash
#!/bin/bash
# Quick checks for agent-generated code

# 1. No edits to generated files
GENERATED=$(git diff --cached --name-only | grep -E '\.(pb|ssz)\.go$')
if [ -n "$GENERATED" ]; then
    echo "ERROR: Agent modified generated files: $GENERATED"
    echo "Edit the .proto or source files instead, then run hack/update-go-*.sh"
    exit 1
fi

# 2. No edits to third_party
THIRD_PARTY=$(git diff --cached --name-only | grep '^third_party/')
if [ -n "$THIRD_PARTY" ]; then
    echo "ERROR: Agent modified third_party files: $THIRD_PARTY"
    exit 1
fi

# 3. Compile check
go build ./... 2>&1 | head -20
```

## The Core Insight

The previous report showed that agentic coding fails when knowledge is implicit. This report's recommendations all follow one strategy: **make the implicit explicit**:

- **Implicit COW protocol** → explicit CLAUDE.md + linter + generic helpers
- **Implicit fork checklist** → explicit script + YAML schema + generator
- **Implicit lock ordering** → explicit CLAUDE.md documentation
- **Implicit file edit boundaries** → explicit pre-commit hook
- **Implicit task risk levels** → explicit Green/Yellow/Red zone table

The codebase stays the same. The knowledge becomes encoded. The agents become effective.
